## 1. 产品定位、目标用户与核心痛点

**定位**：一款 Obsidian 社区插件（按可发布标准打造、MIT 开源免费），为"按文件夹组织成体系内容并发布到 Quartz"的作者提供三件一体的能力：文件夹级自定义排序、自动维护的文件夹索引页（MOC）、静态可发布的系列导航（上一篇/下一篇/返回总览）。

**目标用户**：
- 主画像：教程/连载作者。以文件夹为项目单位组织系列文章，部署 Quartz 发布，要求发布后的页面自带目录和翻页导航。（当前用户即需求方本人：约 500 篇笔记、git 同步、最大单文件夹 20 个 .md、每篇笔记 frontmatter 均有 created/updated）【已确认】
- 次画像：重度文件夹整理者，需要文件浏览器排序之外的、随文件本身走的顺序数据。

**核心痛点**：
1. Obsidian 核心文件浏览器至今不支持手动拖拽排序（2026-10 核实官方 changelog），手动排序只能依赖社区插件，而主流排序插件的顺序数据存放在插件私有 data.json，不随文件走。
2. 系列笔记阅读缺少"上一篇/下一篇"上下文导航。
3. MOC/目录页手动维护成本高；现成方案（Folder Overview、Waypoint）以动态代码块渲染，发布到 Quartz 后变为死代码。【已核实竞品】
4. Dataview 方案需在每篇笔记手贴代码块，且无法自动跟随自定义排序。【已确认：需求方拒绝该方案的动机】

**产品形态**：桌面版 Obsidian 插件（TypeScript），纯本地运行，无后端、无遥测。v1 不承诺移动端。

## 2. 核心概念与业务规则

### 2.1 术语与判定

- **受管域（managed scope）**：拥有受管索引页的文件夹，及其规则覆盖的范围。**判定 = 标记即受管**：扫描发现带 `is-index: true` 且含标记区块的文件，该文件夹即为受管域（含 git 恢复、手工拷贝而来的情况）。【暂定】
- **v1 限定受管域必须是非根文件夹**（根目录作为全域是过度设计，series 模式将吞掉全库，留待后续版本）。【暂定，采纳审查建议】
- **索引页**：frontmatter 含 `is-index: true` 且正文含插件标记区块的 .md 文件。文件名可配置（默认 `目录.md`，预设 `index.md`，可自定义）。**识别只看标记，不看文件名**。【已确认】
- **order**：笔记 frontmatter 中的数值字段（正整数，10000 步长，见 §2.3），排序唯一真相源，随文件走。
- **标记区块**：`<!-- chapter-trail:begin -->` 与 `<!-- chapter-trail:end -->` 之间；区块内归插件独占，区块外归用户，重建时绝不触碰区块外内容。【已确认】
- **状态即文件**：插件不维护私有数据库。排序、模式、排除等全部状态存在于笔记 frontmatter 与索引页 frontmatter 中，随文件/文件夹移动自动迁移。【已确认的设计原则】
- **自动化边界**（对 P0 矛盾的裁决）：批量**重建**类操作（重建索引、重建注入、批量清除）一律手动触发；以下两项为用户明确确认的**单文件自动化例外**：① 文件进入受管域时自动写入 order；② 文件移出受管域时自动清除其 order 与注入标记。watcher 除此之外只更新内部判定与面板状态标记，不改写任何文件。【已确认：改进4 + 手动触发原则的边界说明】

### 2.2 两种模式（每个受管域二选一，写在索引页 frontmatter 的 `mode` 字段）

**independent（独立，默认）**【已确认】
- 链条 = 本层直系 .md 按 order 排序；受管子文件夹各自成链，互不串联。
- 直系文件与受管子文件夹在同一数值空间**混排**；受管子文件夹的 order 存于其自己的索引页 frontmatter。【已确认：废除 subfolder-order 数组】
- 索引页内容 = 直系文件条目（排序输出）+ 子文件夹条目：
  - 受管子文件夹 → 链接到其索引页（以其索引页 frontmatter 的 order 参与混排）；
  - 未受管子文件夹 → 纯文本列出、不可点，排在所有受管条目之后，按文件名自然排序（保留此设计以完整呈现结构，符合需求方示例意图）；【已确认：2026-10-04 转正】
  - 空子文件夹 → 不列出；【暂定】
  - 排除的子文件夹 → 不显示。

**series（系列串联）**【已确认，特化为"虚拟路径混排"】
- 一次声明吃掉整个子树：链条 = 递归收集域内全部 .md（排除项除外），按各自 frontmatter 的 order **全局排序**成一条链。
- 子文件夹只是路径前缀/分类标签：不持有 order、不建索引页、不参与排序计算。
- 索引页内容 = 全子树缩进树列表（Markdown 嵌套列表）；**无索引页的子文件夹仅作为纯文本粗体目录节点展示（不加链接），仅 .md 叶子条目带标准 Markdown 跳转链接**——避免 Quartz 渲染出无效跳转。【已确认：2026-10-04 评审修订】
- "返回总览"统一指向域根索引页。【已确认】
- 域内出现另一个受管索引页（嵌套 is-index）= 冲突：面板标红，提供三选：降级为普通笔记（移除 is-index 与标记区块，文件保留）/ 删除 / 将其所在文件夹加入 excluded-folders。【暂定——"吃掉子树"与"嵌套受管"逻辑不相容，必须裁决】

**索引页自身的身份（两种模式通用）**【暂定，采纳审查建议】：索引页不入本域链条、不被注入导航、不获本域 order；作为父域的受管子条目出现时，以其 frontmatter 的 order 代表该子文件夹。

### 2.3 排序规则

- **order 格式与步长**：order 统一使用**正整数**，初始/重排步长为 `10000`（10000, 20000, 30000…），避免浮点精度与零碎尾数，对 Obsidian Properties 面板与 Dataview 最友好。【已确认：2026-10-04 评审修订，替代原小数方案】
- **插入逻辑（中点整数化）**：在两篇之间插入取整数中点 ⌊(orderA + orderB) / 2⌋（10000 与 20000 之间 → 15000；10000 与 15000 之间 → 12500）；日常插入只写这一个文件，Git diff 最小化。【已确认】
- **间隙阈值与重排**：相邻间隙 < 10（无法再舒适插入整数）时，拖拽结束后将该域标黄"建议重排"（不弹系统对话框打断）；若此时用户仍向过密间隙拖入文件，则先自动重排该域、再按中点落位，并在面板提示本次自动重排。【已确认：阈值行为；自动重排后插入为暂定】重排（Re-index）将该域全部 order 按 10000 步长规范化重写（10000, 20000, 30000…），不改变链条次序；另有手动重排命令。【已确认】
- **进入受管域**（按事件来源区分）【暂定，采纳审查建议补全】：
  - 新建文件（create 事件，单个）→ watcher 自动写入 order = 域内当前最大值 + 10000（链条尾部）；【已确认：改进4；步长随 v1.3 更新】
  - 从未受管位置移入（rename 事件）→ 清除遗留 order（若有）+ 面板蓝标"待排序"，不自动赋值；
  - 批量新增（防抖窗口内 ≥ 5 篇，典型如 git 同步/批量导入）→ 整批蓝标"待排序"，不逐个写入，避免写入风暴与顺序不确定；
  - 受管域之间移动 → 清除 order，目标域蓝标"待排序"，不静默插入目标链条。【暂定】
- **移出受管域**：watcher 自动清除**该文件自身**的 order 与全部注入标记（自动化例外②）；同时**将其原所属域在面板标黄"索引/链条过期"**——原域索引页中的失效条目、左右邻居 callout 中的旧指向，由用户手动"重建索引/重建注入"修复，形成清理闭环。【已确认：2026-10-04 评审补全】
- **回声抑制**：插件自身写入触发的文件事件不再次进入处理流程。【暂定】
- order 相同（平手）：按文件名自然排序兜底，面板黄色警告。【暂定】
- **首次声明管理**：仅对缺失 order 的笔记批量赋值，初始顺序 = 文件名自然排序，赋 10000 步长整数（10000, 20000, 30000…）；**已有 order 值原样保留**并在面板黄标提示"顺序可能不符合预期"，由用户重排归一；确认框显示将写入的文件数。（修订：v1 不沿用/不覆盖来自其他工具的已有值——插件无法区分字段来源，保证退出可逆性优先。）【暂定，采纳审查建议】

### 2.4 排除规则

- **笔记级**：frontmatter `excluded: true` → 不入链、不入索引、不参与排序计算。【已确认】已注入导航的笔记被标记排除后，下次"重建注入"时剥离其注入标记。【暂定】
- **文件夹级**：索引页 frontmatter `excluded-folders: [相对路径...]`（**相对域根**）→ 整个子文件夹不入链、不入索引。【已确认该机制存在；两种模式通用（修订），路径基准为暂定】
- 文件夹改名/移出域时，rename 兜底同步重写索引页 frontmatter 中的路径引用。【暂定】
- 排除不删除任何文件；被排除文件夹若自身含有带标记索引页，其自身域仍成立，只是不作为父域条目、不被父域吸收。【暂定】

### 2.5 索引页规则

- **产权**：frontmatter 中的插件键（is-index、mode、excluded-folders 及子文件夹 order）与标记区块归插件；**用户已有的其他 frontmatter 键原样保留**；区块外用户自由书写，任何重建操作不触碰。【已确认产权划分；键保留细则为暂定】
- **冲突处理**：目标文件夹已存在无标记的同名文件时，弹窗三选一：采纳（原内容整体保留在区块外、原有 frontmatter 键保留，仅追加插件键）/ 重命名保留原文件 / 取消。【已确认】
- **唯一性**：同一文件夹出现两个带标记索引页 = 红标冲突，用户择一保留或都不保留。【暂定】
- **删除索引页 = 域解散**：面板提示该域残留 order 的笔记清单（vault 级"遗留 order"提示，可一键清除，清前确认）。【暂定】
- **条目格式**：标准 Markdown 链接，完整相对路径、特殊字符 URL 编码（如 `[第三章](./第三章.md)`）；不使用 wikilink。【已确认】
- **日期**：读取笔记 frontmatter 的 created / updated；显示哪个日期为设置项：created / updated / 两者，默认 created；格式 YYYY-MM-DD。【已确认：2026-10-04 转正】
  - 支持格式白名单：Obsidian date/datetime 属性类型、ISO `YYYY-MM-DD`、ISO `YYYY-MM-DDTHH:mm(:ss)` 文本；其余视为解析失败。【已确认：2026-10-04 转正】
  - 解析失败或字段缺失 → 该条目不显示日期。【已确认】子文件夹条目不显示日期。【暂定】
- **更新时机**：索引页内容与注入标记的**重建**全部手动触发（命令或面板按钮）；watcher 检测到删除/新增/移动/改名时，仅更新内部判定并将对应域在面板标黄"索引过期"。【已确认：手动触发，自动化例外见 §2.1】
- **设置变更**（索引文件名、日期显示方式）→ 相关域标黄"索引过期"，等待手动重建。【暂定】

### 2.6 导航注入（默认关闭）【已确认】

- **设置项**：`写入上下篇导航`，默认关闭。关闭时**不写入任何文本、不提供动态渲染形态**；跳转命令（见下）不修改文件，仍然可用。【措辞修订，采纳审查建议】
- **硬性不变量**：注入开关关闭期间，插件不得向任何笔记写入或修改任何注入内容（含包裹标记与 `[!chapter-trail]` callout）。开关是注入写入路径的唯一闸门——代码层面物理隔离，而非"写入后再清除"；回归测试必须覆盖"关闭期间执行排序/重排/重建索引，笔记 diff 中无注入痕迹"。order 字段的写入与注入开关无关，仅发生在用户显式管理动作时（开始管理、拖拽重排、新文件入域）。【已确认：零注入写入；order 与注入开关解耦为范围澄清，暂定】
- **开启**：弹确认框（"将向 N 篇笔记写入导航标记"）；为链条中每篇笔记在 frontmatter 之后第一行（无 frontmatter 则文件首行之前）与文件末尾各插入一段**带成对注释包裹标记**的可折叠 callout：`<!-- chapter-trail:nav-begin -->` … `<!-- chapter-trail:nav-end -->`，内部为 `> [!chapter-trail]- 上一篇：[xxx] | 总览：[目录] | 下一篇：[yyy]`。识别、重建、清除仅针对包裹标记内的内容；用户手写的同类型 callout 不受影响。callout 类型标识含连字符若遇 Obsidian 解析限制，回退为 `chaptertrail`（并入 T0 验证）。【暂定：包裹标记机制，采纳审查建议】
- **内容矩阵**【暂定】：顶部与底部内容相同；首篇省略"上一篇"位，末篇省略"下一篇"位；单篇链条仅含"总览"位；callout 内链接同为标准相对路径 md 链接。
- **"总览"指向**：所属链条的域索引页（series → 域根；independent → 本文件夹索引页）。【已确认】
- **关闭**：主动询问"是否清除全部已注入标记"，用户选择后执行或保留。【已确认】
- **跳转命令**（不修改文件）：跳转上一篇 / 下一篇 / 打开索引页——基于当前排序计算，对注入关闭的用户同样可用。【暂定】

### 2.7 管理面板（MVP 核心 UI）【已确认：进 MVP】

- 每个受管域一张卡片：
  - **序列列表**：拖拽重排。series 域 = 扁平全量列表，条目显示路径前缀；independent 域 = 直系文件与受管子文件夹混排。
  - **状态标记**：红 = 断链（条目指向不存在的文件）或结构冲突（嵌套索引、双索引页）；蓝 = 待排序；黄 = 索引过期 / order 平手 / 间隙阈值 / 遗留顺序提示。（红/黄/蓝三色图例，红色合并语义）【已确认：2026-10-04 转正】
  - **操作按钮**：重建索引、重排 order、（注入开启时）重建注入。（修订：删除原"清理失效条目"——与重建索引重叠。）
- Vault 级：启动时一次全量扫描；面板顶部汇总（受管域数量、异常计数、遗留 order 提示）。
- 面板中可对任意文件夹执行"开始管理"（选择模式）。【暂定】
- 实现约束：长列表虚拟化（500 文件域必须流畅）。

### 2.8 生命周期命令

- 开始管理当前文件夹（选模式）／停止管理（删除索引页 = 域解散；询问是否同时清除域内 order 与注入标记）【暂定】
- 重建当前域索引 ／ 重建全部索引
- 重排 order（当前域）
- **全部清除**（可逆性契约）：① 移除所有注入包裹标记内的内容；② 删除索引页（逐域确认）；③ 清除 order 字段（逐域确认；界面明示：将移除该域内**全部** order 字段，可能连带非插件来源的同名字段）。执行后判定标准见 A8。【已确认：必须有完整退出路径；契约细则为暂定修订】

## 4. 竞争差异化与用户留存

**差异化**（对照已核实竞品）：
1. **静态注入 → 发布可用**：导航与目录是真实 Markdown 内容，Quartz 原样发布即可点击；Folder Overview / Waypoint 的动态代码块发布后失效。
2. **状态即文件**：顺序、模式、排除全部存在于笔记与索引页自身，无插件私有数据库，git 友好、跨 vault 可移植、Dataview 可读。
3. **一体化 + 零代码块**：排序、索引、导航一个插件全自动跟随，无需 Dataview 手贴、无需三插件拼凑。
4. **显式且可逆**：默认不写任何笔记、标记区块产权划分、包裹标记精确清除、一键全清除——直接回应"怕插件弄脏 vault"的顾虑（这也是注入默认关的原因【已确认】）。

**留存逻辑**：order、索引页、注入一旦在 vault 铺开，即构成一整套"文件内约定"，替换插件 = 放弃整套约定并手工清理，切换成本自然沉淀；同时清除命令保证退出自由。不以锁定为策略，以约定为粘性。

## 7. 功能验收标准（可测）

- **A1** independent 域（混合：直系文件 + 受管/未受管/空/排除子文件夹）重建索引后：文件按混排序输出；受管子文件夹为链接、未受管为纯文本且排在其后、空与排除的不出现；日期按设置与白名单显示或省略；子文件夹条目无日期。
- **A2** series 域跨 3 层子树：全部 .md（排除项除外）按 order 全局成链；首篇无"上一篇"、末篇无"下一篇"；所有"返回总览"指向域根索引页；索引页为缩进树列表。
- **A3** 注入开关生命周期：关闭状态 → 任何笔记零改动（git diff 为空），且关闭期间执行排序/重排/重建索引等任何操作后，笔记 diff 中不得出现注入内容或包裹标记；开启 → 确认框计数准确、每篇 frontmatter 后一行 + 文末一行、包裹标记齐全、首尾位与单篇链条退化正确；再次关闭 → 清除询问出现，确认清除后仅包裹标记内内容被移除、用户手写 callout 保留、diff 为零残留。
- **A4**（前置：注入已开启）删除链条中一篇笔记：面板出现红色断链标记；"重建索引"后索引页死链消失；"重建注入"后两侧邻居 callout 的 prev/next 正确重连。
- **A5** 移动笔记出受管域：其 order 与注入包裹内容被自动清除；移入另一受管域时目标面板显示"待排序"蓝标；**原所属域同步标黄"索引/链条过期"**，重建后索引页死链与邻居旧指向消失。
- **A6** order 平手：按文件名自然序兜底并出现黄标；执行重排后 order 恢复为按 `10000` 步长递增的规范整数（10000, 20000, 30000…），且链条次序保持不变。
- **A7** series 域内出现 is-index 文件：面板红标，降级/删除/加入排除列表三个操作全部可用且生效。
- **A8** 全部清除命令执行后：所有注入包裹标记与内容被移除；索引页按确认结果删除；order 字段仅在用户逐域确认的范围内被移除；除上述范围外文件内容零改动（可枚举断言，不要求"与安装前逐字节一致"）。
- **A9** 性能【暂定】：1 万篇合成 vault 启动扫描 < 2s；500 文件域拖拽重排响应 < 100ms；该域全量重排 < 5s 且有进度显示。
- **A10** 事件韧性【暂定】：向受管域批量同步 20 篇新笔记 → 整批蓝标"待排序"，无逐个自动写入；插件自身批量写入不触发级联重建（回声抑制）。
- **A11** 同名文件采纳：原有 frontmatter 非插件键全部保留、区块外内容逐字节保留、插件键与标记区块生效。
