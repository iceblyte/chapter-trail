## 第 3 项答疑：为什么必须有 `<!-- chapter-trail:begin -->` 标记？

它是插件的**产权契约**，三件事都靠它：① **识别**——“标记即受管”（PRD §2.1），插件靠它判断哪个文件夹是受管域（不看文件名，拷贝/改名/迁移都不会失效）；② **重建边界**——重建索引只替换标记之间的内容，你写在区块外的序言、后记逐字节不动，没有边界就无法保证这一点；③ **干净退出**——“全部清除”能精确移除插件写入的一切而不碰你的正文。好消息：阅读视图里 HTML 注释**本来就不显示**，你只有源码模式能看到它。如果源码模式里看着难受，可以在设置 → 外观里降低注释亮度，或者后续版本我加一条针对这两行的编辑器淡化样式（CM6 decoration 已具备基建）。

# 第六轮修复（2026-10-25）：打开失败根因定位与修复

## 根因（你提供的控制台输出一锤定音）

```
RangeError: Block decorations may not be specified via plugins
```

这是 CodeMirror 6 的硬性限制：**块级装饰（block widget）只能由 StateField 提供，不允许通过 ViewPlugin 的 decorations 提供**。上一轮的编辑模式导航用了 ViewPlugin——异常在 EditorState 创建时抛出，而打开任何 markdown 文件都要创建 EditorState，所以**所有笔记都打不开**（与受管与否无关，只是你恰好在受管文件夹里测试）。我上一轮加的 try/catch 包不住它：异常发生在 CM 消费装饰结果时，不在我们的计算函数里。

## 修复

editor-nav 从 ViewPlugin 重写为 **StateField**（块级装饰的唯一合法通道）：

- `create` / `update` 时从当前 state 计算（editorInfoField 判定文件身份 → 域查找 → 模型 → 顶部/底部两个 block widget）；
- `provide: (field) => EditorView.decorations.from(field)`；
- NavWidget.eq 防止 DOM 抖动；每次事务重算的成本是两次 range 构造（微秒级）；
- 保留 try/catch 兜底。

## 日期体系统一说明（#5/6/8）

`core/date-whitelist.ts` 重写为 `core/date-value.ts`（纯函数、零依赖、核心层纯净性不变）：
- **解析**：`YYYY-MM-DD`、`YYYY-MM-DD[T或空格]HH:mm[:ss[.sss]]`（可带 `Z`/`±HH:mm` 后缀）、`YYYY/MM/DD`、`YYYY.MM.DD`、`[[...]]` 包裹、YAML `Date` 对象、epoch 数值（合理的毫秒/秒量级）；保留闰年与字段范围校验。
- **显示**：moment 风格令牌 `YYYY YY MM DD HH mm ss`；**没有时间部分的值永远不会补出时间**（`2026-08-28` 在默认格式下仍显示 `2026-08-28`，`2026-09-04 23:40` 显示完整时间）。
- **配置**：三个新设置项默认与"Update modified date"插件一致（`updated` / `created` / `YYYY-MM-DD HH:mm`）；created 属性名留空 = 全局不显示创建时间；修改后自动重扫面板并标黄提示重建索引。
