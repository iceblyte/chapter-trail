# Chapter Trail 验收清单（真机实测）

> 适用版本：main 分支 `1.0.0`（构建产物 `main.js` / `manifest.json` / `styles.css`）
> 测试环境建议：Obsidian Desktop ≥ 1.5.0，准备一个**可丢弃的测试 vault**（建议先用小 vault，最后用你的真实 vault 冒烟）
> 建议同时开着 `git diff` 或源码模式，随时核对"插件到底写了什么"。

## 0. 安装与启动

- [x] **0.1 安装**：把 `main.js`、`manifest.json`、`styles.css` 三个文件拷入 `<vault>/.obsidian/plugins/chapter-trail/`，在设置 → 第三方插件中启用
  - 预期：无报错；左侧丝栏出现 list-ordered（三横线加数字）图标
- [x] **0.2 打开面板**：点击丝栏图标
  - 预期：右侧边栏出现 "Chapter Trail" 面板；空 vault 时显示"还没有受管文件夹"提示 + 底部"＋ 开始管理文件夹"按钮；顶部汇总行显示 `0 个域 · 0 个需关注`（英文界面为 `0 domains · 0 need attention`）与红/黄/蓝三色图例
- [x] **0.3 设置页**：面板 ⚙ 或 设置 → Chapter Trail
  - 预期：五项设置齐全——索引文件名（默认 `目录`）、日期显示（created/updated/both）、**写入上下篇导航（默认关）**、**order 变更后自动重建当前域索引（默认关）**、语言（English/中文）；底部有"清除全部 Chapter Trail 数据"入口

## 1. 开始管理与首次声明（对应原型 04 / PRD §2.3）

准备：文件夹 `教程/`，内含 5 篇无 order 的笔记（建议用中文+数字文件名，如 `01 为什么.md`、`02 怎么做.md`…）。

- [ ] **1.1 两步弹窗（面板入口）**：点"＋ 开始管理文件夹"
  - 第一步：出现文件夹筛选列表，显示每个文件夹的"X 篇笔记 · Y 个子文件夹"；已受管的文件夹灰显"已受管"
  - 第二步：选择 Independent / Series，黄色警告框显示**"将按文件名自然序为 5 篇无 order 笔记赋 10000 步长 order"**与"将创建 目录.md …"
  - 确认后：Notice "✓ 域已创建"；面板出现该域卡片
- [ ] **1.2 首次声明赋值**：打开任一笔记的源码/Properties
  - 预期：按文件名自然序获得 `order: 10000, 20000, 30000…`；**没有任何其他内容被写入**（正文、其他 frontmatter 原样）
- [ ] **1.3 索引页生成**：打开 `教程/目录.md`
  - 预期：含 `is-index: true` 与 `mode`，正文含标记区块内的条目列表；标准相对路径链接（`[01 为什么](./01 为什么.md)`），不是 wikilink
- [ ] **1.4 命令入口**：在域内笔记中执行命令 `chapter-trail: Start managing current folder`（先建一个未受管文件夹测试）
  - 预期：跳过选文件夹直接弹模式选择；在 vault 根目录笔记上执行时提示"vault 根目录不能作为受管域"
- [ ] **1.5 同名采纳（A11）**：新建文件夹 `书单/`，先手写一个 `目录.md`（含自定义 frontmatter 键如 `title: 我的书单` 和正文序言），再开始管理
  - 预期：弹出三选一（采纳/重命名保留/取消）；选**采纳**后——原有键与序言、正文**逐字节保留**（可 git diff 核对），仅追加 `is-index`、`mode` 与标记区块
  - 选**重命名保留**：原文件改名（`目录-旧.md`），新建干净索引页

## 2. 排序与拖拽（原型 01/03 / PRD §2.3，A6）

- [ ] **2.1 面板拖拽**：抓着某行左侧 ⠿ 把柄，把一篇拖到相邻两篇之间
  - 预期：落位后 Notice 显示 `order = 中点值`；git diff **只有这一个文件一行 order 变化**；行序号即时更新
- [ ] **2.2 行右键**：右键任意条目
  - 预期：出现"上移/下移"菜单；点击后等价于拖到相邻位置；点击菜单外或 Esc 菜单关闭
- [ ] **2.3 边缘自动滚动**：在 ≥ 20 条的域里把第一篇拖到列表底部
  - 预期：拖到列表边缘时持续自动滚动，可一拖到底；列表流畅不卡顿
- [ ] **2.4 过密间隙自动重排**：手工把某几篇 order 改得很近（如 `10000/10003/10006`），再向该间隙拖入一篇
  - 预期：Notice"间隙过密 — 已整域重排，再落位该条目"；重排后全部 order 恢复 10000 步长、**链条次序不变**
- [ ] **2.5 平手与重排（A6）**：手工把两篇 order 改成相同值
  - 预期：面板出现黄色"X 个平手 order"芯片，排序按文件名自然序兜底；点"重排 order"后恢复 10000 步长且次序不变，芯片消失
- [ ] **2.6 拖拽回原位**：把一篇拖回它原来的位置
  - 预期：零写入（git diff 为空），无 Notice

## 3. 两种模式与索引页（PRD §2.2/§2.5，A1/A2）

- [ ] **3.1 Independent 混排（A1）**：构造——`读书/`（independent）下：直系笔记 A(order 10000)、子文件夹 `第一部分/`（自己也是受管域，其索引页 order 20000）、直系笔记 B(order 30000)、无笔记的空文件夹、含笔记的未受管文件夹、`excluded-folders` 排除的文件夹
  - 预期（重建索引后）：直系笔记与"第一部分"（作为链接条目）按 order 混排；未受管文件夹以**纯文本**排在所有受管条目之后；空文件夹与被排除文件夹**不出现**；子文件夹条目无日期
- [ ] **3.2 Series 树（A2）**：series 域含跨 3 层的笔记
  - 预期：索引页为缩进树列表；无索引页的子文件夹为**纯文本粗体、无链接**；仅 .md 叶子带链接；日期按设置显示
- [ ] **3.3 日期设置**：切换"日期显示"为 updated / both 并重建
  - 预期：条目日期跟随；无 created/updated 或格式非法（如"明天"）的条目不显示日期；切换设置时 Notice 提示相关域标黄
- [ ] **3.4 用户产权**：在 `目录.md` 标记区块**上方**手写一段序言、区块下方写一段后记，然后重建索引若干次
  - 预期：序言与后记逐字节不动，仅区块内列表变化
- [ ] **3.5 索引文件名设置**：把"索引文件名"改为 `index`
  - 预期：Notice 提示新页面将使用新名字、不重命名任何现有文件；已有 `目录.md` 域不受影响（识别只看标记）；对新域使用 `index.md`

## 4. 导航注入（原型 05-M2/08 / PRD §2.6，A3）

- [ ] **4.1 关闭即零写入（A3 硬性不变量）**：保持注入开关关闭，执行拖拽、重排、重建索引、跳转命令
  - 预期：`git diff` 中**没有任何** `chapter-trail:nav-begin/end` 标记或 callout 出现
- [ ] **4.2 开启注入**：设置中打开"写入上下篇导航"
  - 预期：确认框显示"将向 N 篇笔记写入…"（N=全部域链条文件总数，核对准确）与分块提示；确认后批量写入带进度；每篇笔记在 **frontmatter 之后第一行**与**文末**各有一段 `nav-begin/end` 包裹的可折叠 callout
- [ ] **4.3 内容矩阵**：检查首篇（无"上一篇"）、末篇（无"下一篇"）、中间篇（三位齐全）、单篇域（仅"总览"）
  - 预期：子文件夹内笔记的"总览"链接为 `../目录.md` 形态；链接均为标准相对路径
- [ ] **4.4 阅读视图与折叠**：切换阅读视图
  - 预期：callout 正常渲染、可点击折叠；Obsidian 与（若有）Quartz 预览均无报错
- [ ] **4.5 关闭询问**：设置中关闭开关
  - 预期：设置行内出现"从 N 篇笔记中移除全部已注入标记？[清除标记][保留]"；选**清除**后所有 `nav-begin/end` 与其内容消失、**用户手写的同款 callout 保留**、diff 零残留；选**保留**则标记留存（可稍后经清除向导处理）
- [ ] **4.6 注入关闭时命令**：关闭状态下执行 `Rebuild injection in current domain`
  - 预期：Notice"导航注入未开启 — 请先在设置中打开"，不写任何文件

## 5. Watcher 与事件（PRD §2.3，A4/A5/A10）

- [ ] **5.1 新建文件入域（例外①）**：在受管域内新建一篇笔记
  - 预期：约 1 秒内自动获得 `order = 域内最大值 + 10000`（排到链条尾部）；面板序号更新
- [ ] **5.2 批量同步不写入（A10）**：向受管域一次拷入 ≥ 5 篇笔记（模拟 git 同步）
  - 预期：**没有任何 order 被写入**；面板出现蓝色"X 篇待排序"芯片，待排序行显示蓝点与"—"；可拖拽或重排处理
- [ ] **5.3 移出域自动清理（A5/例外②）**：把一篇已注入域内的笔记（含 order 和导航）移出到不受管文件夹
  - 预期：该笔记的 `order` 字段与导航包裹**被自动清除**；**原域卡片标黄"索引过期"**；面板条目里该文件消失
- [ ] **5.4 域间移动**：把一篇笔记从域 A 拖到域 B
  - 预期：order 与导航被清除；A 标黄、B 蓝标"待排序"，不静默插入 B 链条
- [ ] **5.5 删除链条成员（A4）**：删除（移入回收站）链条中间一篇
  - 预期：面板出现红色"1 处断链"，条目以红色删除线 + "找不到文件"呈现；**重建索引**后死链消失、红芯片清除；**重建注入**后两侧邻居的 上一篇/下一篇 正确重连
- [ ] **5.6 回声抑制**：执行一次重建全部索引（多文件写入）
  - 预期：写入过程不触发级联重扫/重复 Notice（控制台无异常刷屏）
- [ ] **5.7 删除索引页 = 域解散**：删除某域的 `目录.md`
  - 预期：面板卡片消失；顶部出现黄色横条"X 个遗留 order 字段 — '<文件夹>' 已解散"；点 **Review** → 危险确认框（显示文件数）→ 确认后遗留 order 全部清除、横条消失

## 6. 冲突处置（原型 02/05-M4 / PRD §2.2，A7）

- [ ] **6.1 嵌套索引冲突**：在 series 域的子文件夹里手工创建一个带 `is-index: true` + 标记区块的文件
  - 预期：父域卡片红色"嵌套索引冲突"芯片，条目区显示冲突文件说明与处置提示
- [ ] **6.2 三选一处置**：点 Resolve…
  - **降级为普通笔记**：该文件 `is-index`/标记区块被移除、文件保留，其子树笔记回归 series 链条
  - **删除文件**：移入系统回收站，冲突消失
  - **排除该文件夹**：父域索引页 frontmatter 的 `excluded-folders` 追加该子文件夹，冲突消失且该子树不再被吸收
- [ ] **6.3 双索引页**：在同一文件夹再放一个不同的标记索引页
  - 预期：两页均按孤儿处理，该文件夹不成为域（v1 行为：面板不显示该域；处置方式为手工删除其一）

## 已知边界与说明

1. **命令面板名称**在语言切换后需重载插件才更新（设计如此，DESIGN §4.9）。
2. **受损标记区块**（用户删掉 `end` 标记）在下次重建索引时按"begin 到下一个 begin 或文件尾"整体替换修复——修复会消费该区间的内容，重建前请自行确认。
3. **Quartz 实测**（T0-1 三项：链接 slug / callout 呈现 / `目录` 文件名）不在本清单内，需要你的真实 Quartz 部署验证；对应常量在 `src/constants.ts`，实测后如需切换成本最低。
4. 移动端不在 v1 范围（`isDesktopOnly: true`）。
5. 批量写入进度条当前以 Notice 形式呈现（写入文件数较多时可观察到）；取消按钮出现在进度 Notice 内，取消在当前块完成后停止。
